# 双 GPU 实验优先级与 100 小时额度方案（条件预算，不是执行授权）

## 约束

- 魔搭剩余约 100 小时：**用户截图显示值，非通过云端 API 核实**；是否累计运行时间/有效GPU时间、休眠规则、到期日、是否重置均未知。不得按 100h 必然可用开始长任务。
- 腾讯 Cloud Studio T4 按用户提供费率 1.2 机时/小时；与魔搭 100 小时额度**不是同一账本**。
- 实验期间先记录实际 GPU 名称、ROCm/HIP/CUDA、吞吐、墙钟时间、磁盘/网络；若有成本费用，记录实际账单。基线和冻结评测不足则不开始正式模型更新。
- 任何通过任务都必须有**原始输入、母体与代码SHA、数据来源分区、配置/seed、训练状态、逐题结果和实例外备份**。TEST2不得提前打开。

## 魔搭 100h 条件使用池（建议上限，不是任务必须跑满）

| 优先级 | 项目 | 额度上限 | 成功证据 | 停止条件 |
|---|---|---:|---|---|
| P0 | GPU/ROCm/持久存储和 Agent 可用性 | 3 h | ROCm GPU device、数值有限、持久路径及下载测试 | GPU 不可用或平台有权限限制 |
| P1 | 六类 YOLO / 旧组件的小规模推理与复测 | 5 h | 同一可信 SHA 的推理输出、峰值显存、与 CPU/T4 差异 | 模型不能加载/输出漂移无法解释 |
| P1 | Qiora BF16 训练链路可行性（不含正式训练） | 8 h | 有条件传输、BF16/SDPA、load/infer/adapter forward/backward，保存恢复 | 未获权重传输授权、空间/时间不足 |
| P2 | 视觉模型研究性改进实验 | 12 h | 先确定不混锁定 TEST 的复现基线与数据准入；小型消融 | 无可靠 DEV 或无实际提升迹象 |
| P2 | Qiora-KER 专家训练（另行授权） | 28 h | G0 PASS 后按 Domain/Evidence 对照分阶段执行；真实知识/证据评测 | 旧 compact-v3 GPU 接口未接通、能力退化、恢复失败 |
| P3 | 多模态/舌象 + Qiora 系统研究 | 14 h | 文本证据链和视觉标签均有可靠来源，固定对照评测 | 不具备合法的数据准入或推理框架失配 |
| 保留 | 失败恢复、重复验证、权重回传及余额保护 | **30 h** | 分配时重新审核 | 不可为“用完额度”强制消耗 |
| **合计** | | **100 h** | | |

这只是优先级上限账目：后续项目不因有空闲 GPU 自动启动；前一个实验失败可将余额留存。训练实际可能远少于上限；不要把所有阶段同时交给不同 Agent 启动。

## 腾讯云 T4 优先安排

- 第一次 **只做短时 CUDA preflight 和当前 YOLO11n 合成推理**；初始评估窗口由用户单独决定，控制台核对余机时与实际费率。
- 若 T4 被证明可用，优先进行六类 YOLO11n 的真实 DEV 复测与较小视觉模型的参考评估，不尝试将完整 Qiora BF16 8B 模型作为 T4 原生主要任务。
- 两端的视觉结果要在相同模型 SHA、预处理、输入及后处理参数下比较；数值容差要预注册，不声称 CUDA 与 ROCm bitwise 相同。

## 实验必要元数据

每次保存 `RUN_ID`、平台、开始结束时刻、使用配额、Git commit、母体 SHA、数据集 SHA 和合法使用范围、预处理、训练超参、optimizer/scheduler/RNG、样本簇 ID、评测脚本 SHA、原始/规则化输出、checkpoint SHA 与外部重载证明。

## P0→P2 决策关口

1. 环境真实兼容（not CPU-only）；GPU 型号 / gfx 确定；无其他用户任务被侵扰。
2. 持久路径及外部回传完整；一次小文件的 PUT→独立 GET→SHA 校验。
3. YOLO 可信模型推理闭环；不对医疗意义下结论。
4. Qiora BF16 迁移需要独立授权，且迁移计划不会占尽持久存储；在下载前估算新模型/optimizer、日志、数据、checkpoint 的峰值。
5. 正式 Pro 新协议 GPU 接入并数值通过；Base/Domain/Evidence 同题对照指标冻结，才谈 G1/G2。

## 云端 Agent 组织

每台云端仅一个主执行任务。两个环境禁止同时访问或覆盖同一远程输出目录，训练期间备份按可恢复检查点进行。所有正式实验都由本地主项目维护唯一身份证据；Agent 只运行受限任务，不自发扩展训练。
